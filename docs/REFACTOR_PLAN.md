# AI Stock 全面重构方案

日期：2026-09-27

状态：规划稿。本次仅检查现有源码并编写方案，尚未改动运行代码、数据库或部署。

## 1. 重构目标与取舍

把当前项目升级为稳定、可复现、便于学习和比较策略的本地量化研究与模拟交易工具。

优先顺序：回测正确性与数据可信度 > 长时间运行稳定性 > 参数与结果持久化 > 性能 > 界面体验 > 新算法。

核心约束：

- 保留本地、AI、机器学习运行模式，以及现有五种模型。
- 保留激进、均衡、保守、自定义；每种模型、每个档位的设置独立保存。
- 保留三种训练方式及回退关系：自己训练自己 -> 按行情分类 -> 全部混合。
- 保留年度标签的人工修订、每股自动切档、三档分别自动学习、评分权重调整。
- 默认允许长时间训练，不恢复固定的年度计算超时；必须能停止、恢复、查看进度。
- 参数候选可双向变化、跨越档位风格；档位风格由评分目标体现。只保留算法合法性和资源容量检查，例如概率范围、正整数、显存是否足够。
- 手机和电脑使用同一后端状态；网页关闭不会停止后台任务。
- 重构效果以正确性、稳定性、效率和可解释性衡量，收益提升通过独立测试验证。

## 2. 源码检查得到的问题

以下为静态检查结论，不等同于已完成全量回测或崩溃复现。

| 问题 | 当前代码依据 | 影响 |
| --- | --- | --- |
| 职责过于集中 | `web.py` 3,860 行；`PaperTradingDashboard` 同时管理 HTTP 状态、配置、行情、回测、自动学习和持久化 | 修改互相牵连，难以单独测试和定位 |
| 计算阻塞页面 | `state()`、`run_once()`、`run_backtest()` 使用同一个锁；回测整个流程持锁 | 即使提交到了后台线程，页面状态读取仍可能等待计算结束 |
| 配置多处重复 | 后端 defaults/profile/override、前端 fields/defaults/formPayload 分别维护 | 切档、保存、恢复和应用建议容易出现不同步 |
| 任务与结果保存不完整 | 任务主要存于内存字典；自动学习只保留有限候选、轮数和最新结果 | 刷新后的恢复与服务重启后的续跑缺少完整任务记录 |
| 页面获取的数据过大 | `/api/state` 返回配置、行情历史、回测、年度标签和学习结果；前端定期拉取 | 手机首屏等待、重复解析和绘图成本高 |
| 静态资源无法缓存 | `_send_file()` 对所有文件设置 `Cache-Control: no-store` | 每次加载重复下载 JS/CSS |
| 同一根行情成交 | 回测先读取当天收盘价生成信号，再以该收盘价成交 | 对收盘后才能算出的信号，成交条件偏理想 |
| 模拟成交过于简化 | `Bar` 仅收盘价和成交量；`PaperBroker` 即时成交、无费用与交易可用数量 | 难以模拟滑点、停牌、买卖单位和各类标的交易约束 |
| 风控执行顺序不合理 | `RiskManager.build_order()` 达到日亏损限制就直接返回，然后才判断止损及卖出 | 停止买入的规则可能同时阻断降低风险的卖出 |
| 行情分类被策略结果影响 | 年度 worker 使用持有收益和策略回撤调用 `_auto_learn_year_regime()` | 同一年行情可能随候选参数变成不同分类，专项评分比较失真 |
| 对默认候选额外扣分 | `_score_auto_learn_candidate()` 对 `baseline` 固定扣 0.015 | 默认参数与新参数不是完全同口径比较 |
| 神经网络训练缺少验证环节 | MLP/CNN 根据训练损失提前结束，并把整个训练集一次放入设备 | 无法有效验证泛化，数据增大后内存、显存压力较大 |
| 特征计算重复 | 对每个样本截取历史前缀；CNN 窗口内再次逐点计算指标 | 多年、多股票、多候选计算时有大量重复工作 |
| 行情来源口径需核验 | 当前交易池主要是 ETF，AKShare 日线适配统一调用 `stock_zh_a_hist` | 应按资产类型使用正确接口，核验空数据和备用源是否一致 |
| 数据和发布缺少版本管理 | SQLite 主要通过建表初始化；依赖清单存在宽松范围与 CUDA 固定版本两种口径 | 升级、迁移、不同电脑安装后结果难以保证一致 |
| 缺少自动化验证 | 当前仓库未发现测试目录和 CI 配置 | 训练时间、标注、保存、移动端等问题容易反复出现 |

## 3. 目标结构

采用模块化 Python 后端、独立计算进程和组件化网页。仍然以单台电脑运行、一个启动入口为默认形态。

```text
手机 / 电脑浏览器
        |
        v
网页界面 + HTTP API
        |
        +-- 设置 / 模拟账户 / 结果查询
        |
        +-- 任务调度器 -- 独立 CPU / GPU 计算进程
                             |
                             +-- 训练 / 回测 / 自动学习
        |
        +-- SQLite：设置、任务、交易、实验索引
        +-- 本地文件：行情、特征、模型、完整结果
```

建议模块：

```text
src/ai_stock_bot/
  api/            请求校验、路由、事件推送、访问控制
  domain/         行情、信号、账户、成交、任务等数据结构
  settings/       配置定义、档位默认值、保存、迁移
  data/           行情适配器、交易日历、校验、缓存
  features/       指标计算、序列样本、标签、时间切分
  models/         注册表和各算法适配器
  strategies/     本地规则、概率决策、行情校准、AI 接入
  execution/      风控、模拟撮合、持仓与交易流水
  backtesting/    回测时钟、执行流程、基准、统计
  learning/       候选生成、跨年份评分、三档最优记录
  jobs/           排队、执行、停止、检查点、恢复
  persistence/    数据库、迁移、文件存储
frontend/         组件化网页
tests/            时间正确性、配置、任务、回测与界面测试
```

目录按实际职责逐步拆出，不要求每个小功能都建立抽象层。

技术选择：后端 FastAPI + Pydantic；前端 Vue 3 + TypeScript + Vite，状态管理使用 Pinia，图表按需引入 ECharts；保留 scikit-learn、XGBoost 和 PyTorch。数据库先继续 SQLite，启用 WAL、索引、短事务和版本迁移。行情及特征使用 Parquet/NumPy 等适合批量读取的文件格式。

FastAPI 只负责请求和任务入口，重计算放到独立进程。其官方文档也区分轻量后台任务与重计算需求：[FastAPI 后台任务](https://fastapi.tiangolo.com/tutorial/background-tasks/)。

## 4. 数据与回测可信度

### 4.1 建立可冻结的数据集

- 明确日线/分钟线、时区、交易日期、资产类型、OHLCV、成交量单位、复权方式和来源。
- ETF 使用对应行情接口；股票、跨境 ETF、黄金 ETF、债券 ETF 分别记录资产属性。参考 [AKShare ETF 历史行情](https://akshare.akfamily.xyz/data/fund/fund_public.html)。
- 首次下载后增量更新，补齐缺口；下载失败时保留已有数据与来源信息。
- 创建数据集版本和内容摘要；同一组对比实验固定同一数据版本，备用源切换也记录版本。
- 在界面显示每只标的的实际开始/结束日期、有效数量、缺失区间、上市时间和实际训练长度。
- 历史前复权价格可能随后续权益事件改变，需要冻结数据版本并记录复权因子。撮合用可交易价格，指标用约定口径；分红和收益核算保持一致。
- 不为不存在的历史数据补造样本，不把不同来源和不同复权口径的数据直接拼接。

### 4.2 强制分开三个时间概念

每次实验分别记录训练区间、验证区间、测试区间，并另外记录指标预热区间。

例如：测试 2022 自然年、训练窗口三年，训练数据只取测试开始前实际存在的历史数据。训练窗口改成五年，2022 的测试日期与行情内容摘要必须保持一致。

- 样本的未来标签可以使用未来价格，但整个标签结束时间必须早于该次训练截止时间。
- 五日反弹标签需要完整五日后续行情；不能把末端不足五日的样本当作完整标签。
- 时间切分边界清除跨界标签；间隔长度按标签跨度和评价方式设定。
- 标准化、类别权重和概率校准仅从对应训练/验证区间计算。
- 年度事后牛熊标签用于分析已完成年度和组织历史样本；交易当天切档使用当天已知信息。
- 人工年度标签记录修改时间与适用范围；包含未来全年信息的修订不可用于更早时点的训练或切档。
- 一个测试区间只取约定日期内的数据；缺失或未上市标的按明确规则排除并披露覆盖率，不能悄悄缩短所有标的的窗口。

### 4.3 重建模拟成交

- 默认当天收盘后生成信号、下一根可交易行情成交；日线优先使用下一交易日开盘价。
- 统一成交、现金、可卖数量、持仓成本和费用的账本。
- 按资产元数据配置买卖单位、交易时间、T+0/T+1、价格限制、停牌和滑点；规则通过交易所等权威来源核验。
- 同一根 K 线中止盈止损顺序无法判断时采用明确且保守的约定，并在结果中记录。
- 日亏损限制控制新增风险，卖出和止损有独立路径。
- 模拟账户和回测共用决策、风控、撮合规则，使用不同的行情时钟。
- 持有基准使用相同起始现金、交易窗口、费用和可交易资产；明确是否定期再平衡、是否计入分红。
- 输出收益、超额、最大回撤、回撤持续时间、持仓比例、换手、费用、交易数以及现金基准。

历史结果保留为旧引擎结果。修正成交和费用之后，收益改变属于计算口径改变，必须通过手算的小样本解释差异。

## 5. 设置与持久化

后端配置定义成为唯一来源，前端从配置定义生成可调参数、默认值、帮助说明和适用状态。

配置按以下维度组织：

- 账户与执行：起始资产、风控、模拟成交设置。
- 本地策略：四档分别保存买入分和规则。
- AI 策略：四档分别保存提示与适用约束。
- 每种机器学习模型：四档分别保存训练计划、目标、阈值和模型参数。
- 训练资料：训练股票、年度标签、人工修订。
- 自动学习：模型、年份、预算、三类评分权重和连续迭代策略。

保存行为：

- 网页编辑先形成草稿；“保存全部”通过一次事务提交完整设置，返回配置版本。
- 手机和电脑同时编辑时比较版本；旧页面提交不能静默覆盖新设置。
- 切档仅切换当前编辑对象；不会重置另一个档位的数值。
- “恢复当前档默认”和“恢复全部默认”区分范围。
- 应用学习建议保存该模型对应档位的参数与来源，再返回已保存配置；页面刷新后读取同一版本。
- 创建任务时冻结配置快照；任务运行期间更改网页参数只影响新任务。
- 设置、账户、任务和结果分别存储，避免保存设置时覆盖学习历史或模拟账户。
- 提供设置导入/导出、修订历史、数据库备份和迁移校验。

## 6. 后台任务与长期运行

SQLite 中建立 `jobs`、`job_events`、`experiments`、`trials`、`year_results` 和 `checkpoints` 等持久记录。SQLite WAL 支持读写同时进行，但仍只有一个写入者，事务要短，数据库存于本机磁盘：[SQLite WAL](https://www.sqlite.org/wal.html)。

- API 提交后返回任务编号；训练进程不持有网页状态锁。
- 状态包括排队、运行、暂停中、暂停、停止中、停止、成功、失败和中断。
- 进度按已完成股票/批次/年份/候选计算，显示当前阶段与耗时；取消根据时间假推百分比。
- 每个完成的年度、候选和轮次写入检查点；重启后续跑未完成部分。
- 断点续跑同时恢复随机数状态、候选中心、已评估摘要、三档最优和评分版本。
- 父进程监督子进程并接收心跳，使用短间隔检查，避免 `join(None)` 使停止请求无限等待。
- 支持在安全边界暂停、用户立即停止子进程；失败子任务可以重试，不影响网页。
- 默认没有计算墙钟超时；网络下载仍设合理连接/读取超时。无心跳时显示异常并提供停止、重试入口。
- GPU 资源不足可缩小批次；原生崩溃记录退出码、设备和环境，再按配置执行有限重试或 CPU 回退。
- 首期 GPU 同时运行一个重训练任务，CPU 并发按实测内存和算法线程数调度。
- 全部轮数、候选和失败年份保存；页面分页查看，不能用内存截断代替完整历史。
- 默认重启恢复任务记录与待续跑状态；模拟账户自动交易是否重启继续运行单独设置。

## 7. 模型与自动学习

### 7.1 模型适配器

统一实现数据准备、训练、批量预测、模型保存/加载、设备信息和训练报告。RandomForest、HGB、XGBoost、MLP、1D-CNN 各自文件维护参数和实现。

- 模型输出二分类或五分类概率，策略模块把概率变成买入/卖出/持有，风控模块决定允许的订单。
- 区分预测概率、候选排序分与订单条件，避免把不同含义都塞进 `confidence`。
- 行情校准独立于模型：牛市持有耐心、震荡区间、弱市反弹分别可启用、调节和记录。
- 自动切档分别路由到该模型的三档配置；记录每只股票当时采用哪档、为什么切换。
- 训练方式回退统一实现，报告实际样本数量、类别分布、采用的来源及回退原因。
- 同样输入、参数、数据版本和种子支持复现；GPU 在相同环境使用数值容差验证，并记录可能的非确定性。
- 模型文件记录特征版本、目标、训练截止时间、来源和设备；兼容校验后才加载。

### 7.2 修正神经网络训练

- 按时间划分训练与验证集，提前停止以验证指标为依据，并恢复最优权重。
- 用小批量训练和批量预测替代全量张量一次上传；CNN 序列使用共享特征数组构建。
- 按设备能力尝试混合精度，检查数值稳定性和实际加速。小模型未必能获得明显收益：[PyTorch 混合精度示例](https://docs.pytorch.org/tutorials/recipes/recipes/amp_recipe.html)。
- 记录训练/验证损失、类别指标、概率校准效果以及 CPU/GPU 内存峰值。
- 保留当前模型作为基线，模型改动和执行口径改动分开比较。

### 7.3 自动学习的公平比较

- 保留每轮默认参照、粗搜、细搜、随机扰动，三档各自围绕当前最优双向探索。
- 阈值、模型参数、训练窗口和训练方式可以进入搜索；开销较大的参数分层评估。
- 只改买卖阈值或执行规则时复用同一模型的历史预测；影响训练、标签或行情选择的参数变化必须重新训练。
- 候选去重和缓存使用完整配置、数据、代码、种子、训练截止时间和评分版本摘要。
- 专项行情分类由固定市场数据计算，所有候选共享；去除默认候选的额外扣分。
- 未完成必需验证年份的候选标为“不完整”，默认不晋升为可一键应用的最佳建议。
- 专项、兜底和综合权重继续可调；若目标场景没有有效样本，单独显示缺少覆盖，不能以其他场景冒充专项成绩。
- 自动切档关闭时比较单档能力；开启时另外评价组合策略，提供按实际切档划分的统计。
- 参数搜索用开发验证年份；另外保留未参与搜索的日期或标的作最终测试。已经反复调过的 2021-2025 不能再宣称完全未见过。
- 通过时间向前滚动的多个验证窗口评价稳健性，检查最差年份、成本敏感性和小幅参数变化。
- 快速/平衡/深度只改变候选预算与验证深度，不能悄悄改变数据窗口、评分公式或必需验证条件。
- 分阶段筛选、试验剪枝可选，并明确部分验证结果；完整验证之后才比较最终最优。

## 8. 性能优化顺序

先测量一次任务的下载、特征、样本构造、训练、预测、回测和写库耗时，再优化占比最高的环节。

1. 本地行情增量缓存，避免每个候选、每个年份重复联网拉取。
2. 按数据/特征版本向量化计算指标；共享训练数组，CNN 避免窗口内重复计算。
3. 缓存相同训练配置的模型和历史概率，执行规则搜索复用预测。
4. 优化小批量 GPU 训练和 CPU 算法线程数，避免候选并发与算法内部并行互相争抢资源。
5. 计算进程按需要复用并定期回收；通过压力测试决定回收频率，兼顾 CUDA 启动成本和内存增长。
6. API 拆分摘要、行情、结果和历史列表，分页与按需加载；静态文件带版本缓存。
7. 事件推送进度，断线后从事件序号恢复；降级轮询只读取轻量任务状态。

性能目标需在固定机器、固定离线数据集上验证：

- 回测/学习运行时轻量 API 的 P95 响应目标不超过 300 ms。
- 首屏轻量摘要目标不超过 100 KB，完整曲线和历史明细不随摘要返回。
- 热缓存多候选试验争取至少减少一半总耗时；这是目标，先建立基线再判断能否达到。
- 持续运行 24 小时内存无持续累积，设备资源不足不会导致整个服务退出。
- 初始移动端 JS 压缩体积目标不超过 250 KB，图表与学习历史独立加载。

## 9. 界面与使用体验

保留用户熟悉的仪表盘、测试、设置入口，新增内容通过次级页面组织，避免一屏堆积所有参数。

- 电脑采用侧栏与宽内容区；手机采用底部导航和单列布局，同一套路由与状态。
- 设置保留账户、本地、机器学习、训练、AI、规则分类。机器学习内每种模型有独立参数页、四档切换及已保存状态。
- 保存/恢复保持设置顶部；注明操作范围，显示未保存改动和保存版本。
- 训练数据、年度标签和自动学习分别按需加载；标签按名称折叠，显示年度曲线和人工修订来源。
- 自动学习先显示三档最佳摘要；详细五年表现、参数差异、轮次和候选列表折叠、分页。
- 电脑三档并列比较，手机切换档位查看；只有真正的宽表格局部横向滚动。
- 回测显示实际训练/测试区间、数据完整度、费用、持有基准和失败说明。
- 图表支持日期缩放、价格坐标、悬浮明细、账户/单股切换以及小型黄色买入点、蓝色卖出点。
- 图表展示可降采样，计算用完整数据；交易点单独保留，不能因曲线采样而漏掉标注。
- 页面隐藏时暂停无关刷新；任务继续由服务端执行。
- 中文内容统一 UTF-8；文案与策略说明从配置定义生成，测试乱码、溢出、长名称和不同屏幕尺寸。

按页面拆分加载和长列表虚拟化符合 [Vue 性能建议](https://vuejs.org/guide/best-practices/performance.html)。换框架本身不会自动解决慢，需要同时修复锁、响应体积、计算与缓存。

## 10. 公网演示、发布与维护

- 公网默认只读演示；保存参数、启动重计算、应用建议、账户操作需要管理员身份。
- Cloudflare 隧道保留，登录、权限检查和请求额度由服务端执行。
- 限制静态文件路径范围、请求体大小，统一 JSON 错误与错误编号；界面不把网关 HTML 当作回测数据。
- 凭据存于本机环境或专门的本机凭据配置，日志和导出自动脱敏；普通发布包不包含个人数据库或登录资料。
- 结构化日志带任务、候选、年份、模型和设备信息，提供可导出的诊断包。
- 建立健康检查：服务、数据库、任务执行器、磁盘、GPU 和行情来源分别显示状态。
- 依赖使用锁定清单；CPU 基础版与 GPU 支持分别发布，实盘券商依赖变为可选组件。
- Windows 发布包包含运行环境、已构建网页和启动器；启动器检测端口与依赖，显示地址、日志和启动失败原因。
- 网页保持首选使用方式；PWA 或桌面外壳放在后续阶段，计算仍由后端执行。
- 用户数据目录与程序目录分开，升级前备份、升级后迁移。程序回滚不自动恢复旧数据库；需要对应备份或明确兼容迁移。
- GitHub CI 验证测试、静态类型、构建和发布包；CPU 测试常规执行，CUDA 校验在有合适设备的环境执行。

## 11. 分阶段实施与验收

| 阶段 | 工作与交付 | 通过条件 |
| --- | --- | --- |
| 0. 建立基线 | 旧版标记、数据备份、功能清单、固定离线数据、性能基线、小样本手算结果 | 能复现旧结果并说明已知错误；备份可恢复 |
| 1. 数据与执行正确性 | 时间切分、行情资产适配、模拟成交、费用、风控顺序、基准、评分分类 | 未来价格变动不影响此前信号；训练长度变化不改变测试行情；账本符合手算 |
| 2. 配置与任务底座 | 统一配置、分档保存、数据库迁移、独立进程、检查点、停止/续跑 | 手机电脑一致；任务运行页面不卡；杀掉 worker 后服务可用，重启能续跑 |
| 3. 模型与搜索 | 模型适配器、验证集早停、特征/模型/预测缓存、三档独立搜索、独立最终测试 | 五种模型均通过短测试；完整年份才能晋升最佳；参数影响可追溯 |
| 4. 前端与性能 | 组件化界面、分页、缓存、推送、交互图表、移动端布局 | 宽屏充分利用空间；手机无整页越界；保存/应用/刷新后结果一致 |
| 5. 发布与迁移 | 访问控制、诊断、文档、CPU/GPU 发布包、端口设置、CI | 干净电脑解压可启动基础版；旧数据可迁移；备份与回滚演练通过 |

实施方式：

- 在独立重构分支分阶段提交；旧服务保持可用，新服务先在另一个端口验证。
- 数据库迁移先在备份副本演练，通过后再切换。
- 模块提取保持行为可比；修正算法或成交错误单独提交并解释收益差异。
- 正确性阶段先用本地与 RandomForest 小样本验证，随后覆盖 HGB、XGBoost、MLP 和 CNN。
- AI 使用短期冒烟验证；验证阶段不运行大量 AI 年度回测。
- 发布前才执行必要的完整跨年份验收与长期稳定性测试。

## 12. 必须覆盖的回归场景

1. 修改未来价格、未来年度标签，不改变更早日期的特征、训练模型与信号。
2. 训练窗口一年/三年/五年/十年时，同一自然年的测试日期和行情摘要一致。
3. 标签跨训练边界、短历史、未上市、缺失交易日、重复数据和错误来源均能明确处理。
4. 收盘生成信号不会提前按同一收盘价成交；现金、仓位、手续费和基准可手算核对。
5. 日亏损限制触发后阻止新增买入，同时允许按规则卖出与止损。
6. 五个模型的四档参数分别保存，跨档、跨模型、刷新、重启和应用建议不互相覆盖。
7. 三档候选共用固定行情分类与评分版本；默认候选与修改候选无额外身份加减分。
8. 回测失败年份明确保存，不参与完整冠军晋升；全部轮次和候选可以分页查询。
9. GPU 不可用、显存不足、原生子进程崩溃、网络断开、浏览器关闭和服务重启均可恢复或报告。
10. 停止无限时长训练不依赖当前年度自然结束；完成的子任务不会因重启重复执行。
11. 单档评价与自动切档组合评价分开，训练方式回退、策略校准与实际设备可追溯。
12. 手机窄屏与桌面宽屏的设置、结果和完整交易标注均可查看，中文无乱码。

第一批实施建议：完成阶段 0 与阶段 1 的小样本验证，再建立阶段 2 的配置和任务底座。这三部分是后续算法、性能和界面提升的基础。
